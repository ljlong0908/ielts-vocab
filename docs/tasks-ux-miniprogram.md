## 2. 前置决策项（拍板后才动工）

### D5 · 底部 tab 栏走哪条路 ⭐ 影响最大

现状：`app.json` **没有 `tabBar` 配置**，8 页全是普通页；首页三入口用 `wx.navigateTo`（`pages/index/index.js:75-85`）。

| 路线 | 做法 | 代价 | 视觉还原度 |
|---|---|---|---|
| **A 原生 tabBar** | `app.json` 配 `tabBar.list` | `stats`/`wrongbook`/`profile` 改 `wx.switchTab`；**switchTab 不支持 URL 参数** | ⚠️ 高度/字号/内边距由框架锁定，**无法完全复刻原型**（原型的 88×48 热区、图标尺寸都会变） |
| B 页面内自绘 | 4 个 tab 页各画一份 `position:fixed; bottom:0` | 4 份代码要同步维护、自己管选中态 | ✅ 与原型 1:1 |

**建议先看真机效果再定**：原生 tabBar 省事但视觉走样；自绘麻烦但可控。原型里的 tab 栏是**自绘形态**，若选原生，需接受视觉偏差并回头改原型。

> ⚠️ 若选原生：`pages/checkin/checkin.js:35` 的 `wx.reLaunch` 也应改为 `wx.switchTab`。

### D6 · 练习页的推进方式 ⭐ 我方原型与现状不一致，需你定

**现状**（`practice.js:77-80`）：答对后 **自动** `setTimeout(next, 900)` 推进，页面**没有「下一题」按钮**。
**原型**：加了一个手动「下一题」按钮（未答对时禁用）。

| 选项 | 说明 |
|---|---|
| A 保持现状（自动推进） | 快节奏，少一次点击；但用户没时间回看解析，答错想多看一眼时题已经跳了 |
| B 改手动（照原型） | 每题的节奏由用户掌控，可回看；多一次点击 |
| C 折中：自动推进 + 可点任意处暂停 | 复杂度最高 |

**这是我在原型里的超纲改动**（原型当时按「四态可玩」做的，加了按钮），严格说**偏离了真实逻辑**。若你要 A，我把原型的按钮去掉；要 B，才动 `practice.js`。

### D7 · 「再学一组」的显示条件

与后端文档 **D1 同一项**（推荐：仅当日已打卡后显示）。前端影响：按钮显隐 + 首页进度卡是否显示「2/5 ＋ 5 加练」。

### D8 · 统计页日历要不要可点

现状日历**纯展示**（`stats.wxml:25-32`，`stats.js` 无 `pickDay`）。原型做成了可点（点某天显示当日详情）。

- 若要做：需要**新的查询能力**（按日期取当日 plan / records），当前无此接口 → 属新增后端工作，**本文不展开**，确认要做再单开。
- 若不做：删掉原型里的可点效果即可（纯原型层差异）。

### D9 · 错题本要不要「错 N 次」

原型给错题卡加了「错 2 次」badge。真实实现需在 `user_words` 侧记录错误次数（**新字段**，`submit_answer` 写入）——属后端工作。**确认要做再单开任务。**

### D10 · `app.json` 标题改不改（**其实不是可选项**）

见 M0。这不是设计决策，是**合规必须**，列在此处只为要一个确认。

### 3.2 M1 · 图标落地（原型表达力的天花板）

**现状**：`miniprogram/` 里**没有任何 svg 或 image 图标**，现有图标是两种 CSS 技巧：
- **喇叭 = CSS 三角形**：`learn.wxss:27-34`、`practice.wxss:34-41`、`wrongbook.wxss:38-43`（`border-left` 造三角形）
- **打卡对勾 = 伪元素**：`checkin.wxss:15-25`

**为什么必须换**：三角形在移动端是**「播放视频」的通用语义**，用在音频上会让人犹豫一下。原型已换成喇叭图形，但——

> ⚠️ **wxml 不支持内联 `<svg>`**。原型里的喇叭 / tab 图标是内联 svg，**落地时必须换**：
> | 方案 | 体积 | 说明 |
> |---|---|---|
> | iconfont（推荐） | 极小 | 一个字体文件带全部图标，可调色。需在 `app.wxss` 引入 |
> | `<image>` + base64 | **每个 2~5KB，10 个图标 ≈ 30KB+** | 零依赖，但膨胀包体、改色要重切图 |
> | `<image>` + 云存储 URL | 0 | 需联网（首屏图标会闪），要配 `downloadFile` 域名 |
>
> 建议 **iconfont**：全站图标一次解决，且描边色可用 CSS 控。

### 3.4 M3 · 底部固定区规范（新增约束）

多页新增「固定底部」元素，需要统一定一套规矩，否则会互相打架：

```css
.bottombar {
  position: fixed; left: 0; right: 0; bottom: 0;
  padding-bottom: env(safe-area-inset-bottom);   /* ⚠️ 必加，避让 Home 条 */
  background: var(--surface);
  border-top: 1rpx solid var(--line);
  z-index: 100;
}
```

**三条硬约束**：
1. **任何页加了固定底部区，必须给 `.page` 加对应 `padding-bottom`**（现 `app.wxss:27` 是 `48rpx`）——否则内容被永久遮挡，且**滚动到底也看不见最后一块**，极易漏
2. `env(safe-area-inset-bottom)` **不能省**，iPhone 上不加会被 Home 条压住
3. 若走原生 tabBar（D5 选 A），固定区要往上让 tabBar 的高度，**该高度不可写死**（机型/版本会变），建议用 `wx.getSystemInfoSync()` 测一次存 `globalData`

### 9.1 M15 · 可读性 token（对比度）—— 必须同步 `app.wxss`

   `grep -n "text-3" miniprogram/` → 剩下的必须都是装饰用途

### 9.2 M16 · 引导页文案区（副标题拆解）—— 本轮用户点名的优化

**原状**（`onboarding.wxml:4`）：`目标要小到不会放弃。之后可以随时修改。` —— 一句话塞了两件**性质不同**的事，且都是最低权重的灰字：

| 半句 | 它其实是什么 | 该待的位置 | 原位置 |
|---|---|---|---|
| 目标要小到不会放弃 | 帮用户**选** 5 还是 10 的**理由** | 问题的正下方（选项之前） | ✅ 位置对 |
| 之后可以随时修改 | 选完之后才成立的反悔**承诺** | 选项的**下方** | ❌ 跑到了选项之前 |

**第三个问题更关键**：这句承诺**在页面上没有任何落点** —— 用户被告知"可以改"，却没有任何线索去哪儿改（真机入口在「我的」页）。属"承诺无法兑现"。

**改法**（原型已实施）：

| # | 改动 | 原型位置 | 落地位置 |
|---|---|---|---|
| 1 | 副标题**只留理由**：`目标要小到不会放弃` | `prototype.html` `.muted` | `onboarding.wxml:4`（删掉「。之后可以随时修改」） |
| 2 | 信息条拆**两行**，一行一件事：`背完会做几道小测，答错的词自动进错题本` / `之后可以随时在「我的」里修改` | `.ob-note` 内加 `.ob-note-line` | `onboarding.wxml` 新增一个 `<view class="ob-note-line">` |
| 3 | 补出**落点**：把「随时修改」由空承诺改成**指明了去哪改** | 同上第 2 行 | 同上（文案照抄） |
| 4 | `.ob-note-line + .ob-note-line { margin-top: 2px }` | 新 CSS | `onboarding.wxss` |

**效果**：选项区只被"建议"引导（读的是问题），说明区只讲"选完怎样"（读的是结果），两条 12px 说明不再同级打架；「承诺」也从"读者得自己猜在哪改"变成"明确看见入口位置"。

> ⚠️ **信息条整条保持不可点**：不加边框 / 箭头 / 主色 —— 一旦有按钮相，会被读成"第三个选项"，反而让用户以为选它就能改。
> **D11（待拍板）**：要不要把这一行做成**真的可点入口**（点进「我的」）？若要，需先确认「onboarding 未完成时允许进『我的』」这个状态是合法的（真机 onboarding 完成后才 `reLaunch` 到首页），否则会做出假交互。

### 9.3 M17 · 字号下限约定

审核口径：**信息性文本 ≥12px**，胶囊标（tag / badge）**11px 为底线**。

| 元素 | 原 | 现 | 说明 |
|---|---|---|---|
| `.tab-label`（tab 栏文字） | 11px | **12px** | 4 个 tab 各 93px 宽，12px×3 字完全放得下 |
| `.cal-week-cell`（日一二三四五六） | 11px | **12px** | 日历表头，是**信息**不是装饰 |
| `.metric-label`（连续天数 / 累计打卡 / 累计单词） | 11px | **12px** | 指标名要能读 |
| `.root-type`（前缀 / 词根 / v.） | 11px | **12px** | 词根卡片上的分类标 |
| `.tag` / `.wb-count`（推荐、毅力、错 2 次、今日练习） | 11px | 11px（保留） | 胶囊标，11px 是通行下限；**这 10 条是审核里唯一剩下的 INFO** |

### 9.5 M19 · 反馈载体与安全区

| # | 结论 | 落地要求 |
|---|---|---|
| 1 | **固定底栏高的页面不要用 `wx.showToast`** —— 它的位置不可控（居中偏下），在有底栏的页会被按钮压住（审核 `TOAST_COVER`）。原型按「当前页底栏高 + 16px」动态定位，真机要自绘 toast 或改顶部提示 | 若坚持用 `showToast`，只用于无底栏页（learn / practice） |
| 2 | **每个固定底部区都要避让 Home 条**：`padding-bottom: calc(24rpx + env(safe-area-inset-bottom))` | ⚠️ tab 栏形态（`.bottom.flush`）的避让写在**外壳**上，不能只写在 `.tabbar` 里，否则外层仍为 0（审核 `SAFE_AREA` 就是这么发现漏掉的） |
| 3 | 可点元素要有**按压反馈**：小程序没有 `:active`，`<button>` 用原生 `hover-class`，`<view>` 要自己加 `.hover` 类并在 `touchstart/touchend` 切换 | 原型 `.btn/.ob-option/.tab/.cal-cell/.pf-goal/.wb-item` 都已有 `:active`，落地逐个对应 |
